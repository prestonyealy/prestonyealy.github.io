Hardware architecture

I built the circuit and the firmware as one system.

Four push buttons supplied player input to the Arduino Uno. Four LEDs and a piezo buzzer returned visual and audio feedback. I calculated current-limiting resistors for 5 V operation, then programmed the input handling and game behavior in C++.

Idle→Generate sequence→Playback→Read player→Compare→Feedback
Signal integrity

Debounce the buttons

One physical press can create several rapid electrical transitions. Input debouncing prevents those transitions from becoming false moves.

Program structure

Use finite states

Explicit game states separate sequence playback, player entry, comparison, success, and reset behavior.

User feedback

Map light to sound

Frequency-mapped audio reinforces each LED channel and makes success or failure immediately legible.

Work completed

Prototype, circuit, and firmware.

  • Built and wired the Arduino Uno prototype with four button and LED channels plus a piezo buzzer.
  • Calculated the LED current-limiting resistors for the 5 V circuit.
  • Programmed randomized sequence arrays, input debouncing, finite-state game logic, and frequency-mapped audio feedback in C++.
